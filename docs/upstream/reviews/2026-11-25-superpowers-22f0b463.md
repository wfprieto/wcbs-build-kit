## Decision reasoning and follow-up gates

The canonical decisions are the fourteen dated rows in
[ADOPTION_LEDGER.md](../ADOPTION_LEDGER.md). This section supplies evidence and
follow-up conditions rather than a second disposition table.

- **D01:** WCBS brainstorming already reads context before questions, proposes
  approaches and saves an approved design. Retuning questions needs direct,
  indirect and pressure scenarios under WCBS authority. Upstream's opt-out
  still removes its own design gate; do not copy that exemption into APIVR.
  Preserve matrix capabilities 2–5 and their existing evidence limits.
- **D02:** WCBS writing-skills already routes deep material to linked
  references. Its size audit counts lines, while upstream tests a strict
  20,000-byte ceiling. All current WCBS SKILL.md files are below that ceiling;
  the largest is subagent-driven-development at 13,592 bytes. Before changing
  budgets or splitting policy, demonstrate a compaction-loss scenario and
  verify that repair limits, blocker handling and required reference reads
  survive fresh-runtime compaction. No native compaction test was run here.
- **D03:** Inspect upstream
  [fix-loop](https://github.com/obra/superpowers/blob/22f0b463e7a5e579904dd6211a520321035526f7/skills/subagent-driven-development/references/fix-loop.md)
  and [final-review](https://github.com/obra/superpowers/blob/22f0b463e7a5e579904dd6211a520321035526f7/skills/subagent-driven-development/references/final-review.md).
  Extraction does not remove their five-round adjudication/parking and
  one-wave residual-finding policies. WCBS requires covering tests plus
  independent re-review for material findings and explicit unresolved-evidence
  states. Keep those gates in the canonical controller.
- **D04:** Upstream resolves helper workspaces from the current repository,
  supports explicit `-C`, rejects missing/unborn repositories where HEAD is
  needed, prints native Windows paths and accepts worktree `.git` files.
  WCBS's Node entrypoints and command forms differ. A separate adaptation
  needs wrong-cwd, no-repository, unborn-HEAD, external-plan, linked-worktree,
  spaced-path and PowerShell-readable-output fixtures; preserve exact
  base/head ancestry and scope guards. Static inspection is not a passing
  fixture for these cases.
- **D05:** The local WCBS CLI reproduces Task 6 choosing Task 6b and silent
  truncation at a heading inside an unclosed fence. Exact identity matching,
  code-fence tracking and explicit invalid-plan failure need a separate
  test-first change in `scripts/task-brief.mjs`; include alphanumeric/dotted
  IDs, same-prefix siblings, closed/unclosed fences, translated headings,
  no-match and nested task cases. These observations justify prioritizing
  follow-up, not claiming the parser has been repaired.
- **D06:** WCBS already has a PowerShell-specific Copilot registration, a
  separate POSIX bridge and Node-rendered native/blocked envelopes. Upstream's
  no-fork shell path and Bash/zsh/quiet-exit behavior are not a compatible
  replacement for those payloads. Any performance or fallback proposal needs
  measured startup latency plus empty-PATH, EPIPE, shell-startup-contamination

  equivalence and latency measurement were not performed in this review.
